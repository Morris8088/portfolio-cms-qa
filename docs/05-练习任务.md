# 05 · 练习任务（自己动手的那一半）

> 骨架和两个范例已经跑通，剩下 27 条是留给你的。
> 按关推进，**每关都跑一次 `npm test`**，看到绿了再进下一关。
> 卡住再看提示，别一上来就翻答案 —— 答案其实就在 `portfolio-cms/backend/test/api.test.js` 里，
> 但先自己想一遍，收获完全不同。

## 开始前，记住两件事

1. 把 `test.todo('...', )` 改成 `test('...', async () => { ... })`，
   Playwright 那边是把 `test.skip` 改成 `test`。
2. **每完成一条，去 `cases/testcases.json` 把它的 `status` 从 `practice` 改成 `automated`**。
   报告读的是这份清单，不改的话报告会一直显示"练习位"。

---

## 第 1 关 · 把一条 TODO 变成真用例（先求跑通）

**目标**：只做 `TC-API-010`（正确账号密码返回 200 与 token）。

**动手**：

1. 打开 `tests/api/smoke.test.js`，看 `TC-API-001` 的三段形状。
2. 打开 `tests/api/auth.test.js`，把第 1 条 `test.todo` 改成 `test`。
3. 从 `./helpers/client.js` 引入 `api`，发 `POST /api/auth/login`，
   断言 `status === 200`、`data.token` 存在、`data.user.username === 'admin'`。

**验收**：`npm run test:api` 里 TODO 数从 23 变成 22、pass 从 7 变成 8。

**卡点自查**：路径写对了吗？`body` 传对象就会自动加 JSON 头（看 `client.js` 第 30 行）。

---

## 第 2 关 · 登录与鉴权整组（5 条）

**目标**：`TC-API-011 ~ 014`。

**提示**：

- 011：两种失败**分别发两次请求**，断言状态码相同、`data.error` 也相同。想一下为什么。
- 012：只传 `{ username: 'admin' }`，别传 password。
- 013：`api('/api/auth/me', { token: 'abc.def.ghi' })`，注意 `client.js` 会把它拼成 `Bearer ...`。
- 014：`const token = await login()`，再 `api('/api/auth/me', { token })`。

**验收**：`npm run test:api` 全绿，TODO 数再减 4。

---

## 第 3 关 · 文章 CRUD（6 条，最难的一关）

**目标**：`TC-API-020 ~ 025`，文件 `tests/api/posts.crud.test.js`。

**这一关真正在练的是「用例不互相污染」**：

1. 从 `../../fixtures/factory.js` 引入 `makePost()`，每次造一篇标题带随机后缀的新文章。
2. 需要令牌：每个用例开头 `const token = await login()`。
3. 用例**自己创建的数据自己删**。可以用 `test` 的第二个参数 `t`：
   `t.after(async () => { await api('/api/posts/' + id, { method:'DELETE', token }); })`。
4. 024 的关键：先造一篇 `status: 'draft'`，游客 GET 详情应 404，带 token 应 200。

**为什么必须随机标题**：slug 是从标题生成的，写死 `测试文章` 的话
第二次跑就撞上 409 —— 用例变成「只能跑一次」，CI 上第二次必红。

**验收**：连着跑两次 `npm run test:api`，两次都全绿（这才能证明没污染）。

---

## 第 4 关 · 查询与边界（6 条）

**目标**：`TC-API-030 ~ 035`，文件 `tests/api/posts.query.test.js`。

**提示**：

- 033：把 `data.items.map(p => p.views)` 取出来，和 `[...views].sort((a,b)=>b-a)` 做 `deepEqual`。
- 034：`sort` 传 `'created_at;DROP TABLE posts'`，断言 200 且 `items` 还是数组 ——
  表没被删说明白名单挡住了。想一下为什么这条比"返回 400"更合理。
- 030/031 都不要断言具体有几篇，只断言「每一项满足条件」或「total=0 且 items 为空」。

---

## 第 5 关 · 上传安全（6 条）

**目标**：`TC-API-040 ~ 045`，文件 `tests/api/uploads.test.js`。

**这一关有个陷阱**：`helpers/client.js` 的 `api()` 会把 `body` 做 `JSON.stringify`，
但上传要发的是 `FormData`，**必须原样交给 `fetch`**。
文件头部注释里给了可直接抄的三行写法。

用 `fixtures/factory.js` 里的 `PNG_1PX` 和 `makeTooLargeImage()`，别往仓库塞大文件。

**验收**：跑完去 `portfolio-cms/backend/uploads/` 看一眼，文件数应该没变
—— 因为 `sut-server.mjs` 把上传目录指向了临时目录。这就是隔离生效的证据。

---

## 第 6 关 · 后台 E2E（4 条，选做）

**目标**：`TC-E2E-010 ~ 013`，文件 `tests/e2e/admin.spec.js`。

**注意**：默认页面靶子是 demo 构建（假后端，数据存在浏览器里）。
要做 `TC-E2E-013`（发布后退出登录仍能被读者看到）这种真链路，
需要本地前后端联调环境：

```bash
# 终端 1：被测后端
cd ../portfolio-cms/backend && npm start          # 3001
# 终端 2：被测前端 dev
cd ../portfolio-cms/frontend && npm run dev       # 5173，vite 已配好 /api 代理
# 终端 3：本工程
E2E_BASE_URL=http://127.0.0.1:5173/ npm run test:e2e
```

**验收**：4 条从 `skipped` 变成 `passed`。建议先把 010/011/012 做掉，013 最后做。
