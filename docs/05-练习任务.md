## 二、五组里最值得精读的五行

**① 防账号枚举**（`tests/api/auth.test.js`）

```js
assert.equal(wrongPassword.data.error, unknownUser.data.error);
```

两次失败**同状态码、同文案**。如果后端哪天把「用户不存在」单独写出来，这条就红。
一条断言背后是一个真实安全知识，比十个 `status === 200` 有说服力。

**② 用例自清理**（`tests/api/posts.crud.test.js`）

```js
t.after(async () => {
  for (const id of ids) await api(`/api/posts/${id}`, { method: 'DELETE', token });
});
```

登记在 `t.after` 而不是写在用例末尾 —— 断言中途抛错也会执行清理。
30 条接口用例共用一个内存库，只要有一条留下草稿，后面的 `TC-API-004`（游客列表不见草稿）就会红。
**测试之间互相污染，是自动化测试最常见的翻车原因。**

**③ 注入要验"表还在"**（`tests/api/posts.query.test.js`）

```js
const after = await api('/api/posts?pageSize=50');
assert.ok(after.data.total > 0, 'posts 表必须还在 —— 注入没有被执行');
```

只断言「非法 sort 返回 200」是不够的：万一 `DROP TABLE` 真执行了，第一次查询可能照样 200。
**再查一次，才能证明数据没被破坏。**

**④ 缺陷探针不写成期望值**（`tests/api/uploads.test.js`）

```js
console.log(`[已知风险 BUG-005] 伪装成 .png 的脚本上传返回 HTTP ${disguised.status} ...`);
```

实测是 201，说明后端只查扩展名、不嗅探内容。这里**故意不写** `assert.equal(status, 201)`：
那是缺陷，不是契约。把它固化成期望值，将来被测项目修好了测试反而变红。
正确做法是记录证据、影响、修复建议，见 `docs/03-缺陷清单.md`。

**⑤ 跨角色业务流程**（`tests/e2e/admin.spec.js`）

```js
await page.getByRole('button', { name: '退出' }).click();
await page.goto('./');                       // 刷新，确保数据是从存储里读出来的
await expect(page.locator('a.post-card h3.title').filter({ hasText: title })).toBeVisible();
```

刷新那一步是刻意的：不刷新的话，文章可能只是组件内存里还留着，
并不能证明「持久化 → 退出登录 → 公开列表」这条链路真的通了。

## 三、两个容易被误判的决策

### 1. 为什么 `TC-E2E-012` 从「密码错误」改成了「必填校验」

原计划写「密码错误给出提示且停留登录页」。但默认页面靶子是 **Demo 构建**，
它的假后端 `mockAdapter.js` 为了演示方便，登录接口**接受任意账号密码直接返回 200**。
在这上面写「密码错误」永远测不出真实行为，只会得到一条假绿或一条永远红的用例。

处理方式是**换到能测的层次**：

- 页面层 `TC-E2E-012` 改测前端自己的必填校验（这是真实的前端行为，能测到）；
- 真实后端「密码错误 → 401 + 统一文案」由接口层 `TC-API-011` 覆盖。

想测真正的密码错误联动，需要把 `E2E_BASE_URL` 指向本地前后端联调环境
（后端 3001 + `vite dev` 5173，vite 已配好 `/api` 代理），那属于另一套环境，不是默认回归的一部分。
**知道自己在测哪个环境、这个环境能验什么，是测试设计的一部分。**

### 2. 为什么「39 条全绿」还要写一条遗留风险

全绿只说明**这 39 条断言描述的行为符合期望**，不代表被测系统没有缺陷。
BUG-005 在断言覆盖范围之外：白名单里的 `.png` 扩展名确实被允许，
只是没人校验文件内容。测试工程师的价值不只是让 CI 变绿，还包括把发现的边界如实交出去。
报告里那块「遗留风险」就是干这个的，面试时主动讲比被问出来强。

## 四、想继续深入，可以做的五件事

按投入从小到大：

1. **给 BUG-005 补一条"修复后自动生效"的用例**：等被测项目加了 magic number 校验，
   把探针改成 `assert.equal(status, 400)`，这条就变成修复的验收标准。
2. **性能基线**：`client.js` 已经把每次请求的 `ms` 带回来了，
   可以给核心接口设阈值并对比多次运行，扩成简单的趋势图（现在只有 `TC-API-001` 的 < 1s 冒烟）。
3. **跨浏览器**：`playwright.config.js` 现在是单项目 + 系统 Chrome；
   加 Firefox / WebKit project 就能验兼容性，注意 CI 里要装对应浏览器。
4. **多环境矩阵**：CI 里用 `E2E_BASE_URL` 再跑一次线上站点作为发版后抽查，
   和本地靶子分开报，别让外网抖动污染日常回归。
5. **覆盖率联动**：把被测项目 `npm test -- --coverage` 的结果也汇总进报告，
   和黑盒用例数并列展示 —— 白盒覆盖率 + 黑盒主流程，两套视角互补。
